## Bugs & Fixes
- **Calendar Date State Initialization**: Calendar currentMonth state should initialize from selectedDate if available, otherwise new Date() to prevent calendar starting at wrong month when date is pre-selected
- **ISO Date String Splitting Consistency**: Always use `.split('T')[0]` pattern for date string normalization vs other splitting approaches - ensures consistent YYYY-MM-DD format across all date comparisons
- **Calendar Grid Week Boundary Calculation**: Calendar grid generation requires careful date manipulation - `startDate.setDate(startDate.getDate() - startDate.getDay())` ensures Sunday start even across month boundaries
- **RSS Item Deduplication After Parallel Fetch**: Must deduplicate and sort items after parallel RSS fetching but before scraping to maintain source metadata mapping through the pipeline
- **Source Metadata Preservation**: When deduplicating items, use Array.find() to map back to original source associations rather than losing source context
- **Error Collection vs Article Collection**: Failed scrapes can still produce articles (with RSS content fallback) - separate error collection from article collection logic
- **Topic Matching Requires Fallback Keywords**: When mapping host topics_of_interest to content keywords, must provide fallback logic (topic.replace(/_/g, ' ')) for topics without explicit keyword arrays
- **Infinite Loop Prevention in Rebalancing**: Host swapping algorithms require iteration limits and swap validation to prevent endless loops when constraint satisfaction conflicts with quality optimization
- **Participation Bounds Enforcement**: Host rotation systems must validate minimum/maximum participation percentages with hard blocking rather than soft penalties to ensure fairness requirements are met
- **Quality Degradation from Over-Optimization**: Excessive rebalancing attempts can reduce content quality - balance fairness requirements against expertise matching with early termination conditions
- **Personality Score Bounds Checking**: Calculated personality scores must be capped (Math.min(personalityScore, 10)) to prevent weighted calculations from exceeding expected ranges
- **AI Response JSON Parsing**: OpenRouter responses may return malformed JSON requiring try/catch around JSON.parse() with fallback to raw text processing
- **Host Pairing Validation**: Host interaction preferences must be validated before dialogue generation - missing pairing data causes prompt injection failures
- **Empty Content Edge Case**: maintainHostConsistency() requires robust empty/null text handling with early return and meaningful error messages to prevent downstream processing failures
- **Personality Trait Bounds Checking**: Calculated personality scores must be bounds-checked (Math.min(score, 10), Math.max(score, 0)) to prevent weighted calculations from exceeding expected 0-10 ranges
- **Vocabulary Style Penalty System**: Negative scoring for inappropriate vocabulary (precise hosts using "kinda", accessible hosts using 12+ letter words) prevents personality drift in generated content
- **AI Response Structure Parsing Robustness**: parseGeneratedArticle() requires fallback logic for missing TITLE:/EXCERPT:/ARTICLE: markers - unstructured AI responses need graceful handling with fallback to treating entire response as content
- **Content Length Edge Cases**: generateFallbackArticle() must cap content length (Math.min(content.length, wordTarget * 4)) to prevent excessively long fallback articles from source material
- **Quality Score Bounds Enforcement**: calculateArticleQuality() requires Math.max(0, Math.min(score, 10)) bounds checking to prevent scoring algorithms from producing invalid quality ratings
- **Excerpt Generation from Missing Structure**: When AI doesn't provide EXCERPT section, parse first 2 sentences from content as fallback excerpt to ensure complete article structure
- **Validation Score Component Bounds**: Multi-dimensional validation scores must be individually bounded (Math.min(score, 10), Math.max(score, 0)) before weighted averaging to prevent individual components from skewing overall quality assessment
- **Placeholder Pattern Escaping**: Regex patterns for placeholder detection require proper escaping of special characters - unescaped dots/braces in patterns like /\b\.{3,}\b/g can cause false positives or matching failures
- **Empty Content Edge Cases in Validation**: validateArticle() must handle null/undefined/empty string inputs with early return and meaningful error messages to prevent downstream processing failures and NaN calculations
- **Sentence Splitting Edge Cases**: Content coherence analysis using /[.!?]+/ splitting can produce empty sentences - filter with s.trim().length > minimum to prevent division by zero in average calculations
- **Weighted Average Division Safety**: Overall score calculations require non-zero weight totals - Object.values(weights).reduce() sum must be validated before division to prevent NaN results in scoring algorithms
- **Convex Schema Evolution Requires Migration Strategy**: Adding new storage fields requires both schema updates and database migration considerations - new fields should be optional initially to prevent existing data conflicts
- **File Upload Content-Type Detection Edge Cases**: Browser File objects may have incorrect or missing MIME types requiring fallback detection based on file extensions - audio files particularly prone to content-type mismatches

## Decisions
- **OpenRouter TaskType Extension Over New Infrastructure**: Adding ARTICLE_GENERATION to existing TaskType enum provides immediate AI integration with model optimization - leverages established infrastructure patterns for 90% time savings
- **Editorial DNA Deep Integration Over Surface Application**: Comprehensive prompt engineering incorporating values, perspectives, and angles from editorial system creates authentic content generation rather than superficial tag application
- **Structured Response Parsing Over Unstructured Output**: TITLE:/EXCERPT:/ARTICLE: format with dedicated parsing logic ensures reliable content extraction from AI responses - prevents downstream processing failures
- **Multi-Dimensional Quality Scoring Over Binary Validation**: Quality assessment using length adherence (±50 words), structure analysis (title/excerpt/paragraphs), analytical depth detection, and placeholder avoidance produces actionable 0-10 scores for content filtering
- **Intelligent Fallback Generation Over Hard Failures**: Fallback article creation using source material and editorial tone prevents total system failures while maintaining brand consistency
- **Convex File Storage Over Direct Database Storage**: File upload workflow using Convex storage APIs provides scalable file management with automatic CDN optimization vs storing binary data directly in database
- **Comprehensive Validation Over Trust-Based Uploads**: Multi-layer file validation (existence, size, content-type) prevents corrupt uploads and provides detailed error feedback vs accepting uploads without verification
- **ConvexHttpClient Over Direct API Calls**: Using official Convex HTTP client provides proper authentication, error handling, and type safety vs manual HTTP requests to Convex endpoints
- **Chunked Batch Processing Over Single Large Operations**: Processing file uploads in configurable chunks (3 concurrent) with delays prevents API rate limiting and provides better progress tracking vs attempting all uploads simultaneously
- **Configuration-Driven CDN Over Hardcoded URLs**: StorageProvider enum with transformUrl() methods enables flexible CDN configuration per storage backend vs fixed URL transformations
- **Progressive Enhancement Storage Migration Over Hard Cutover**: Implementing storage fallback chains allows gradual migration between storage providers without service disruption - enables testing new storage while maintaining existing functionality
- **Lazy Firebase URL Resolution Over Eager Loading**: AudioPlayer loads Firebase URLs only when needed (autoLoad=false) or play button pressed to minimize unnecessary API calls and improve performance - app/components/AudioPlayer.tsx:39, 142
- **Separate Loading States Over Single Boolean**: AudioPlayer uses distinct state variables (isLoading, hasError, isBuffering) for different loading conditions enabling granular UI feedback vs generic loading state - app/components/AudioPlayer.tsx:25-34
- **Direct HTML5 Audio URL Assignment Over Framework Abstractions**: Setting audio element src directly after Firebase URL resolution provides reliable playback vs using React refs or state-based src binding - app/components/AudioPlayer.tsx:62, 148
- **CDN Fallback Strategy Over CDN-Only Approach**: CDN service includes health checks and automatic fallback to direct storage URLs ensuring audio availability even when CDN fails - src/lib/cdn.ts:107-109
- **Direct URL Usage with CDN Enhancement Over Storage Path Resolution**: AudioPlayer components should receive direct URLs enhanced with CDN utilities rather than resolving storage paths - separates storage concerns from UI components and leverages existing fallback infrastructure
- **Central Secrets Management Over Distributed Key Storage**: ~/.secrets file provides centralized, secure API key repository across projects vs storing keys in multiple .env.local files - reduces exposure surface and enables consistent key rotation
- **Comprehensive .env.example Documentation Over Minimal Templates**: Creating detailed configuration templates with service descriptions, acquisition instructions, and requirement groupings reduces developer onboarding friction vs bare-minimum key listings - serves as self-documenting setup guide
