## Bugs & Fixes
- **RSS Item Deduplication After Parallel Fetch**: Must deduplicate and sort items after parallel RSS fetching but before scraping to maintain source metadata mapping through the pipeline
- **Source Metadata Preservation**: When deduplicating items, use Array.find() to map back to original source associations rather than losing source context
- **Error Collection vs Article Collection**: Failed scrapes can still produce articles (with RSS content fallback) - separate error collection from article collection logic
- **Topic Matching Requires Fallback Keywords**: When mapping host topics_of_interest to content keywords, must provide fallback logic (topic.replace(/_/g, ' ')) for topics without explicit keyword arrays
- **Infinite Loop Prevention in Rebalancing**: Host swapping algorithms require iteration limits and swap validation to prevent endless loops when constraint satisfaction conflicts with quality optimization
- **Participation Bounds Enforcement**: Host rotation systems must validate minimum/maximum participation percentages with hard blocking rather than soft penalties to ensure fairness requirements are met
- **Quality Degradation from Over-Optimization**: Excessive rebalancing attempts can reduce content quality - balance fairness requirements against expertise matching with early termination conditions
- **Personality Score Bounds Checking**: Calculated personality scores must be capped (Math.min(personalityScore, 10)) to prevent weighted calculations from exceeding expected ranges
- **AI Response JSON Parsing**: OpenRouter responses may return malformed JSON requiring try/catch around JSON.parse() with fallback to raw text processing
- **Host Pairing Validation**: Host interaction preferences must be validated before dialogue generation - missing pairing data causes prompt injection failures
- **Empty Content Edge Case**: maintainHostConsistency() requires robust empty/null text handling with early return and meaningful error messages to prevent downstream processing failures
- **Personality Trait Bounds Checking**: Calculated personality scores must be bounds-checked (Math.min(score, 10), Math.max(score, 0)) to prevent weighted calculations from exceeding expected 0-10 ranges
- **Vocabulary Style Penalty System**: Negative scoring for inappropriate vocabulary (precise hosts using "kinda", accessible hosts using 12+ letter words) prevents personality drift in generated content
- **AI Response Structure Parsing Robustness**: parseGeneratedArticle() requires fallback logic for missing TITLE:/EXCERPT:/ARTICLE: markers - unstructured AI responses need graceful handling with fallback to treating entire response as content
- **Content Length Edge Cases**: generateFallbackArticle() must cap content length (Math.min(content.length, wordTarget * 4)) to prevent excessively long fallback articles from source material
- **Quality Score Bounds Enforcement**: calculateArticleQuality() requires Math.max(0, Math.min(score, 10)) bounds checking to prevent scoring algorithms from producing invalid quality ratings
- **Excerpt Generation from Missing Structure**: When AI doesn't provide EXCERPT section, parse first 2 sentences from content as fallback excerpt to ensure complete article structure
- **Validation Score Component Bounds**: Multi-dimensional validation scores must be individually bounded (Math.min(score, 10), Math.max(score, 0)) before weighted averaging to prevent individual components from skewing overall quality assessment
- **Placeholder Pattern Escaping**: Regex patterns for placeholder detection require proper escaping of special characters - unescaped dots/braces in patterns like /\b\.{3,}\b/g can cause false positives or matching failures
- **Empty Content Edge Cases in Validation**: validateArticle() must handle null/undefined/empty string inputs with early return and meaningful error messages to prevent downstream processing failures and NaN calculations
- **Sentence Splitting Edge Cases**: Content coherence analysis using /[.!?]+/ splitting can produce empty sentences - filter with s.trim().length > minimum to prevent division by zero in average calculations
- **Weighted Average Division Safety**: Overall score calculations require non-zero weight totals - Object.values(weights).reduce() sum must be validated before division to prevent NaN results in scoring algorithms
- **Convex Schema Evolution Requires Migration Strategy**: Adding new storage fields requires both schema updates and database migration considerations - new fields should be optional initially to prevent existing data conflicts
- **File Upload Content-Type Detection Edge Cases**: Browser File objects may have incorrect or missing MIME types requiring fallback detection based on file extensions - audio files particularly prone to content-type mismatches
- **Storage API Response Validation Required**: Cloud storage APIs can return success status with empty/invalid URLs requiring additional validation of returned storage URLs before considering upload successful
- **Missing Generated API Functions During Development**: Convex development may encounter missing generated functions requiring temporary naming workarounds or direct HTTP client usage until generation completes
- **Buffer vs File Handling in Node.js vs Browser**: Storage upload implementations must handle both Node.js Buffer objects and browser File objects with different property access patterns and conversion requirements
- **Score Precision Normalization**: Multi-factor scoring systems require consistent precision - Math.round(score * 1000) / 1000 pattern ensures 3-decimal consistency across similarity, topic relevance, and combined scores preventing floating point comparison errors
- **Topic Relevance Score Range Validation**: calculateTopicRelevance returns 0-10 scale but relationship scoring expects 0-1 range - must divide by 10 (/10) when using topic scores in weighted combinations to prevent scale mismatches
- **Empty Relationship Array Handling**: enhanceWithContext must handle empty relatedStories arrays gracefully - return original article with hasRelatedSection: false rather than attempting processing on empty arrays
- **Source Story Self-Reference Prevention**: Relationship detection must exclude source story from candidate matching using URL comparison (story.url === article.sourceStory.url) to prevent articles from being marked as related to themselves
- **OpenAI v3 createCompletion API Deprecation**: Legacy completion API no longer available - must migrate to chat completion format with system/user message arrays for continued functionality
- **Token Limit Management in Legacy to Modern Migration**: Modern chat APIs may require different token calculation - OpenRouter automatically handles token limits vs manual tracking in legacy APIs
- **Multi-Host Complexity Threshold**: Stories below 7.0 complexity should not trigger multi-host discussion generation - over-engineering simple stories wastes resources and produces verbose content for straightforward topics
- **Host Count Validation**: Multi-host discussions must enforce 2-4 host limits with graceful fallback to 2-host dialogue when insufficient hosts available - prevents system failures and maintains quality standards
- **Theme Detection Edge Cases**: Story theme classification requires minimum confidence thresholds to prevent miscategorization - stories without clear thematic indicators should fallback to general news discussion format
- **ElevenLabs API Response Buffer Handling**: Audio API responses return Buffer objects requiring proper binary data handling - `response.arrayBuffer()` then `Buffer.from()` conversion necessary for Node.js file system operations
- **Audio Duration Validation Edge Cases**: Generated audio files must have reasonable duration bounds (minimum 1 second, maximum based on text length) to prevent empty files or excessive content from being accepted
- **Cache Key Generation for Binary Content**: Audio caching requires content-based cache keys using text input rather than file content since binary audio data changes with each generation even for identical text
- **ElevenLabs Model Parameter Validation**: API requires specific parameter ranges - stability (0-1), similarity_boost (0-1), style (0-1) with validation to prevent API errors from invalid parameter values
- **Binary File Stream Validation**: Audio file corruption detection requires checking for valid audio headers and minimum file size thresholds before accepting generated content as successful
- **Voice ID Validation for API Calls**: ElevenLabs requires valid voice IDs for generation - configuration must include voice ID validation and fallback handling for missing or invalid voice configurations
- **FFmpeg Filter Chain Labeling Critical**: acrossfade filter chaining requires consistent sequential labeling ([cf1], [cf2], [cf3]) - inconsistent or missing labels cause filter chain failures and audio generation errors
- **acrossfade vs Concatenated Audio Incompatibility**: acrossfade filter requires individual input files and cannot work on already-concatenated audio - must implement separate afade approach for existing concatenated files using timed fade in/out
- **Filter Syntax Spacing and Bracket Sensitivity**: Complex FFmpeg filter syntax is highly sensitive to spacing, semicolon placement, and bracket matching - minor formatting errors cause complete filter chain failures
- **Two-Pass Implementation Necessity**: Single approach cannot handle both new file processing (acrossfade) and existing file enhancement (afade) - requires separate implementation paths for different audio pipeline states
- **Segment Boundary Requirements for afade**: Retroactive crossfade enhancement of existing files requires knowing segment boundaries and timings - must track segment durations during original concatenation for later enhancement
